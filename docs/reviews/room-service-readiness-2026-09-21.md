**Date:** 2026-09-21

**Method:** six independent expert reviews (one per dimension) against `CLAUDE.md` and Go-at-scale practice; every finding cites `file:line` on this tree.

## Executive summary

The largest request/reply surface in the fleet — 28 RPCs, a 2,695-line `handler.go`, a 47-method `RoomStore` — and the size shows in maintainability, but architecture and performance hold up: every subject comes from `pkg/subject`, all nine cross-site event types ride OUTBOX through `outbox.Publish`, Mongo projection discipline and downstream timeouts were verified end to end. Two correctness bugs need fixing before the next release. In integration, the `moveChat` rebalance federates one `section_moved` event per rewritten row with the same `Nats-Msg-Id` (`requestID:eventType:destSiteID`), so JetStream dedup silently drops every sibling after the first and remote replicas keep stale ordering; the covering test discards the msgID argument. In code quality, `removeMember`/`updateRole` wrap a non-member requester's or target's `ErrSubscriptionNotFound` unconditionally, so a documented `forbidden` reaches the client as `internal` and pages as ERROR. Coverage is 57.3%: the store layer is integration-only, and `ComputeSectionOrder`, `MoveSubscriptionSection` and the `InsertTeamsMeeting` idempotency gate are untested at any layer. The four ROOMS-stream publishes carry no dedup id, so a timeout-retried create yields two channels.

## 2. Code quality — score 3

### Evidence

- [high] Membership-gate errors in `removeMember`/`updateRole` collapse to `internal` instead of the typed not-member sentinel — `room-service/handler.go:700-703`, `:727-730`, `:780-783`, `:692-695` — Each site wraps the requester's/target's `GetSubscription`/`GetSubscriptionWithMembership` error unconditionally (`fmt.Errorf("get requester subscription: %w", err)`; `:782` even says "requester not found"), so a non-member requester or a non-member target gets `code: internal` and an ERROR-level "request failed" log (`pkg/errcode/classify.go:22-23,44-47`) rather than `forbidden`/`RoomNotMember`. `addMembers` does it right (`handler.go:906-912`), and `docs/client-api.md` (Update Member Role, "Target account is not a member of the room") promises a client error. Tests only cover `"db down"` (`handler_test.go:596-609`, `:956-971`, `:990-1000`), so the gap is unpinned.
- [medium] Store leaks the driver sentinel `mongo.ErrNoDocuments` across the store boundary — `room-service/store_mongo.go:366` — `GetSubscriptionWithMembership` returns `mongo.ErrNoDocuments` while every sibling maps to `model.ErrSubscriptionNotFound` (`:267`, `:284`, `:1120`). The handler therefore imports the Mongo driver to check both (`handler.go:790`, `:2027`) and misses it entirely at `:692-695`. CLAUDE.md puts the `ErrNoDocuments` check in the store, not the consumer.
- [medium] 20 of 32 log calls in `handler.go` drop the context and lose trace/request correlation — `room-service/handler.go:1198,1259,1443,1481,1532,1545,1558,1564,1570,1745,1887,1921,1932,1937,1943,1997,2069,2259,2618,2625` — The o11y handler injects `trace_id` from `ctx` (`o11y@v0.12.0/internal/log/handler.go:71-83`), and CLAUDE.md requires the request ID in all log lines; `slog.Error(...)` (no ctx) gets neither. The same message is emitted with `WarnContext` at `:1825` and without at `:1443`/`:1745`, so this is drift, not policy.
- [medium] Silent error discard — `room-service/handler.go:2257` — `if canonData, err := json.Marshal(canonEvt); err == nil {` drops the marshal error with no comment, violating "Never ignore errors silently — comment if intentionally discarded".
- [low] Wire-tier `errcode` constructed inside the store — `room-service/store_mongo.go:1019` — `ListOrgMembers` returns `errcode.BadRequest("list org members for %q", WithReason(RoomInvalidOrg))`; the handler then rebuilds a fresh errcode (`handler.go:422-423`). Tier-1 errcodes belong in handlers; the store should return a domain sentinel like `ErrRoomNotFound`.
- [low] Constructor DI bypassed — `room-service/handler.go:103` (14 positional args incl. three ints and a duration) plus 11 post-construction field assignments `room-service/main.go:383-393` — `handler.dekProvisioner/badge/valkey/graphClient/...` are set after `NewHandler`, so the constructor no longer describes the dependency set; tests build `&Handler{...}` literals directly (`handler_test.go:601`).
- [low] Repeated reconstruction of identical errcodes instead of sentinels — `handler.go:173` & `:276` (`NotFound("user not found", RoomUserNotFound)`), `:446,:482,:577,:622` (`BadRequest("invalid request")`), `:1149,:1160,:1169` (`Unavailable("timeout listing members…")`) — CLAUDE.md prefers package-level sentinels so `errors.Is` works and messages cannot drift; `helper.go` already holds 60+ such sentinels.
- [low] Hard-coded per-handler `5*time.Second` timeouts — `handler.go:1227`, `:1279`, `:2590`, `:2641` — duplicated magic number while `natsrouter.GuardConfig` (`main.go:61`) already carries a configurable `REQUEST_TIMEOUT`.
- [nitpick] Log-and-return — `room-service/memberlist_client.go:358-364` — `WarnContext(...)` then `return errcode.Internal(msg)`, which the router's `Classify` logs again at ERROR; one of the two is redundant.
- [nitpick] Inconsistent bare vs wrapped sentinel returns in the store — `store_mongo.go:939`, `:957`, `:979`, `:1945`, `:1969` return bare sentinels; `:242`, `:267`, `:1120` wrap with context. Harmless for `errors.Is` but the log `cause` loses the id/account on the bare paths.
- [nitpick] Misnamed sentinel — `helper.go:103` / `handler.go:2062-2063` — `errInvalidRestrictedSubject` ("invalid restricted subject") guards body fields `roomId`/`account`, not a subject.

## 3. Architecture — score 4

### Evidence

- [medium] Handler is built in two phases, half by constructor and half by field mutation — `room-service/main.go:357-393`, `room-service/handler.go:52-56,103-120` — `NewHandler` takes 14 positional args, then main sets 11 more deps (`dekProvisioner`, `badge`, `valkey`, `graphClient`, `directoryClient`, `teamsMeetingStore`, limits) by direct assignment. The struct comment admits it ("injected as a field rather than a constructor arg to avoid churning every NewHandler caller"). A `Handler` returned by `NewHandler` is not fully wired, and tests must know private field names — contrary to CLAUDE.md "dependencies injected via constructor".
- [medium] ROOMS stream now carries both commands and post-mutation events, and room-worker consumes both — `room-service/handler.go:2248-2261` publishes `chat.room.canonical.{site}.event.member.muted` onto ROOMS for notification-worker (`notification-worker/main.go:292` filters on it), but room-worker's durable on the same stream has no `FilterSubjects` (`room-worker/main.go:214`; no FilterSubject anywhere in room-worker) and its dispatch falls to `default:` → `slog.Warn("unknown member operation")` + Ack (`room-worker/handler.go:279-284`). Every mute toggle costs room-worker a delivery and a spurious Warn. Command/event mixing on one stream without a filter is an ownership leak.
- [medium] Bootstrap covers one of the three streams the service publishes to — `room-service/bootstrap.go:43-61` creates/verifies only ROOMS, yet the service also publishes to OUTBOX (`handler.go:892-895` via `outbox.Publish`) and MESSAGES-CANONICAL (`handler_teams.go:269`). The stated fail-fast guarantee ("a misprovisioned deploy surfaces at startup rather than at first publish", `bootstrap.go:37-38`) is partial. The disabled path also does a `js.Stream` lookup instead of the CLAUDE.md no-op — defensible, but an undocumented divergence from the convention.
- [medium] Service has outgrown the flat layout — `room-service/handler.go` is 2,695 lines with 28 RPCs (`handler.go:129-155`), `RoomStore` has 45 methods (`store.go:61-285`, mock 959 lines), and `Handler` (`handler.go:47-101`) carries room keys, DEK provisioning, badge cache, subauthcache busting, app tabs/cmd-menus and Teams/Graph. CLAUDE.md sanctions the sub-package layout for request/reply services with a larger surface; this is the canonical candidate. `TeamsMeetingStore` (`store.go:331-342`) already shows the split direction.
- [low] Store layer emits a client-facing errcode — `room-service/store_mongo.go:1019` returns `errcode.BadRequest(..., RoomInvalidOrg)` from `ListOrgMembers`, and the interface codifies it (`store.go:111-113`). Every other not-found is a sentinel (`store.go:13-17`) mapped in the handler; this one leaks wire semantics into the persistence boundary.
- [low] Cross-service wire contract duplicated by hand — `room-service/reader_history.go:491-495` re-declares history-service's `GetMessageByIDRequest` because the original sits in `history-service/internal/models/message.go:74` (itself outside the CLAUDE.md layout). Request/reply structs belong in `pkg/model`; two hand-mirrored copies can drift silently.
- [low] Direct MESSAGES-CANONICAL producer with duplicated envelope logic and a stale comment — `room-service/handler_teams.go:229-273` builds a system `MessageEvent` and publishes to `subject.MsgCanonicalCreated`, the same envelope construction room-worker does at `room-worker/handler.go:558,757`. The doc comment (`handler_teams.go:225-228`) says it is "the same flow room_restricted uses", but `roomRestricted` no longer publishes a message (`handler.go:2185-2191`).
- [nitpick] Exported `Handler`, `MongoStore`, `NewMongoStore` in `package main` — `handler.go:47`, `store_mongo.go:60` — CLAUDE.md says keep handler/store implementations unexported; this is repo-wide convention, so taste only.

### Recommendations

- [medium] Replace post-construction field assignment with functional options (`WithDEKProvisioner`, `WithBadgeCache`, `WithTeams(...)`, `WithLimits(...)`) on `NewHandler` — `handler.go:103-120`, `main.go:383-393` — so a constructed Handler is complete and tests stop reaching into private fields.
- [medium] Give room-worker's ROOMS consumer explicit `FilterSubjects` for the operations it handles (`member.add`, `member.remove`, `create`, `room.rename`), or move `event.member.*` off ROOMS onto its own subject/stream — `handler.go:2258`, `room-worker/main.go:214` — removes a per-mute-toggle redundant delivery and Warn.
- [medium] Extend `bootstrapStreams` to verify (never create) OUTBOX and MESSAGES-CANONICAL on the disabled path, or drop the fail-fast claim from the comment — `bootstrap.go:37-61` — so the startup check matches what the service actually publishes to.
- [medium] Adopt the sanctioned sub-package layout: split `RoomStore` into `SubscriptionStore` / `ThreadStore` / `AppStore` / `MembershipStore` consumed by per-domain handler files — `store.go:61-285`, `handler.go` — shrinking the 45-method mock and making the Teams/app/thread areas independently testable.
- [low] Return a sentinel (`ErrOrgNotFound`) from `ListOrgMembers` and map to `errcode.RoomInvalidOrg` in the handler — `store_mongo.go:1019`, `handler.go:1092-1119`.
- [low] Move `GetMessageByIDRequest` to `pkg/model` and import it from both history-service and `reader_history.go:491-495`.
- [low] Extract the system-message `MessageEvent` builder shared by `handler_teams.go:229-273` and `room-worker/handler.go:558,757` into `pkg/`, and fix the stale "same flow room_restricted uses" comment.
