## Executive summary

The read path is engineered with unusual care — every Mongo read projects, bucket walks are bounded and adaptive, errcode tiering is correct throughout, subjects come from `pkg/subject` and every publish stamps `Timestamp` — and four of six dimensions score 4. It still cannot merge under CLAUDE.md as it stands. Unit coverage is 55.1% because the entire store layer lives behind `//go:build integration` and CI never passes the tag, so 19 integration files (1,900 lines in `write_integration_test.go` alone) gate nothing; the same pipeline's Validate step runs `go build ./history-service/`, which has no Go files under the `cmd/`+`internal/` layout, so it either fails every run or is not gating at all. That layout is itself the only one in the tree and contradicts the CLAUDE.md sub-package exception that names this service as its exemplar. Two contract issues need a decision rather than a patch: `msg.thread` returns replies newest-first while both the canonical doc and the derived view promise oldest-first, and every post-commit canonical publish (edit, delete, pin, react) is fire-and-forget — a lost publish leaves fan-out, search and the preview silently stale with no OUTBOX-style retry. Maintainability is the soft spot: a 342-line hand-wired `main()`, a 9-method `RoomRepository` that leaks preview writes into every cache and breaker decorator, and config validation split across two packages.

## 2. Code quality — score 4

### Evidence

- [medium] CI Validate stage cannot build this service — `history-service/deploy/azure-pipelines.yml:47` — the step is `go build -o /dev/null ./$(SERVICE_NAME)/`, but the entrypoint is `cmd/main.go` and the service root holds no `.go` files. Ran `go build -o /dev/null ./history-service/` on this tree: `no Go files in .../history-service`. The line is a copy of the flat-layout template used by every other service; the sanctioned sub-package layout was adopted without adjusting it, so the pipeline either fails every run or is not actually gating.
- [medium] Log-AND-return on a client-facing handler path — `history-service/internal/service/reactions.go:58-59` — `slog.WarnContext(c, "react: actor not found", ...)` immediately followed by `return nil, fmt.Errorf(...)`; the router's `Classify` logs the returned error again, double-logging exactly what CLAUDE.md §6 "Never log AND return" forbids. The raw wrap also collapses a "subscribed account has no user doc" case to `internal`; if that state is reachable it deserves a typed errcode, if not the log is dead.
- [medium] Warn-level logs on the read hot path bypass context correlation — `history-service/internal/service/messages.go:406` (`readFloorInto`), `messages.go:749,754` (`publishCanonicalBestEffort`), `threads.go:374`, `migration.go:150,156` — ctx-less `slog.Warn` hands `context.Background()` to `logctx.Handler.Handle(ctx, r)` (`pkg/logctx/handler.go:68`), so the request-ID/log-values attached via `c.WithLogValues` (`pkg/natsrouter/context.go:187-188`) and the trace ID never reach these lines. `messages.go:406` and `threads.go:374` carry no `request_id` at all; the others hand-add `request_id` but still lose trace correlation. CLAUDE.md §3 requires the request ID "in all log lines".
- [low] Store methods return bare `err` — `history-service/internal/mongorepo/subscription.go:45` (`return nil, false, err`), `subscription.go:32-35` (`GetSubscription` passes `FindOne`'s error straight through), `mongorepo/app.go:31` (`return "", err`). Only `mongoutil.Collection.FindOne`'s generic "finding subscriptions: %w" (`pkg/mongoutil/collection.go:50`) survives; the method-level "what was I doing" wrap CLAUDE.md §3 mandates is absent, unlike the sibling `room.go:206,218` which wrap correctly.
- [low] Log-AND-return inside the scan helper — `history-service/internal/cassrepo/utils.go:224-226` — `structScan` builds the unmapped-column error, logs it at Warn, then returns it; every caller wraps and returns it upward to the router, which logs again.
- [low] Silently discarded close error — `history-service/internal/cassrepo/pin.go:347` — `_ = iter.Close()` on the scan-error path with no comment; CLAUDE.md §3 requires a comment when an error is intentionally dropped (contrast `rooms.go:137`, which does comment its discard).
- [nitpick] Misattached doc comment — `history-service/internal/readcache/readcache.go:139-148` — the paragraph describing `getOrLoad` (load semantics, cancellation behavior) sits directly above `func (c *ttlCache[V]) remove`, so godoc attaches it to `remove` and `getOrLoad` is undocumented.
- [nitpick] Dynamic slog key — `history-service/cmd/main.go:56` — `slog.Error("invalid config", c.name, c.value)` uses the env-var name as the attribute key, so the field name changes per failure; `"name", c.name, "value", c.value` keeps the schema stable for log queries.

### Recommendations

- [low] Wiring-layer decorators live in `package main` — `history-service/cmd/roomrepo_breaker.go:26`, `cmd/roomtimes_seeder.go:147`, `cmd/main.go:73-84` (`subL2Source`) — they implement `service.RoomRepository`/`SubscriptionRepository` just like `internal/readcache` does, but are unreachable from any other package and split the decorator chain across two locations.
- [low] `$lookup` without the required inline justification — `history-service/internal/mongorepo/pipelines.go:400` (`unreadThreadsPipeline`) — the sibling `userThreadSubscriptionsPipeline` carries `// $lookup justification:` (`pipelines.go:299`); this one has none. Git history on this worktree is too shallow to prove it is grandfathered.
- [nitpick] Dead config: `MetricsAddr` (`history-service/internal/config/config.go:65`) is parsed and never read (no other reference in the service).
- [nitpick] Stale comment: `threads.go:210,274` say room name/type "rode in via the aggregation's rooms $lookup"; the pipeline explicitly has no rooms lookup (`pipelines.go:377-378` — they come from the subscription join).

## 7. Performance — score 4

### Evidence

- [medium] `rooms.get` re-walks Cassandra on every request for rooms that resolve to `previewEmpty` — `history-service/internal/service/rooms.go:129-135`, `:246-247`, `history-service/internal/readcache/readcache.go:266-269` — The preview cache is positives-only and warm-back fires only on `previewFound`, so an old room with no eligible message (never used, or all messages deleted/system) walks `createdAt→now` (up to ~50 partitions at the 360h default, in waves of 8) on every room-list load, per pod, forever. user-service calls `rooms.get` on each list (`user-service/service/subscriptions.go:365`), so this is a steady-state amplifier, not a cold-start cost.
- [medium] Thread-parent listing runs a full `$count` on every page — `pkg/mongoutil/collection.go:93-102` via `history-service/internal/mongorepo/threadroom.go:59,67,76` — `AggregatePaged` wraps `$sort` + `$facet{data:$skip/$limit, total:$count}`; `$limit` inside `$facet` cannot be pushed into the preceding `$sort`, so Mongo materialises the whole sorted thread set for the room and counts it on each page. Cost is O(threads-in-room) per page rather than O(page).
- [medium] `unreadThreadsPipeline` does one `$lookup` per thread room before any limit, and carries no inline justification — `history-service/internal/mongorepo/pipelines.go:136-162` — Every thread in the room is joined against `thread_subscriptions` (indexed point read each), then filtered, sorted and counted. CLAUDE.md requires a `// $lookup justification:` comment on any touched `$lookup`; only the `userThreadSubscriptionsPipeline` one (`:39-55`) has it.
- [medium] Thread-inbox keyset cursor is applied after both `$lookup`s, so paging does not reduce work — `history-service/internal/mongorepo/pipelines.go:61-104` then `:106-113` — For a user with N thread subscriptions every page performs 2N lookups (subscriptions + thread_rooms), an in-memory sort on `tr.lastMsgAt`, and only then drops rows before the cursor. Deep pages cost the same as page one. The design doc rejects denormalising `lastMsgAt` (comment `:52-55`), so this is a known trade, but it is unbounded by `limit`.
- [low] Every paginated reply is JSON-encoded twice — `pkg/pagefit/pagefit.go:144-157` (sizing pass) called from `history-service/internal/service/utils.go:211,240`, then the router encodes the response again. Up to 100 `cassandra.Message` rows (with `Reactions.MarshalJSON` grouping) per LoadHistory/Surrounding. `warnIfStillOversize` (`utils.go:261`) adds a third pass on the timestamp-run path.
- [low] Per-row reflection allocations in the Cassandra scan — `history-service/internal/cassrepo/utils.go:146-165` — `structScan` calls `iter.Columns()`, builds a fresh `colNames` slice and a fresh `vals []any` (27 entries, one `Addr().Interface()` boxing each) for every row; only the tag→index map is memoised (`:103-121`). ~5.5k small allocations per 100-row page that could be hoisted once per iterator.
- [low] Cipher-enabled edit reads and decrypts the row twice — `history-service/internal/service/messages.go:502` (`findMessage` → `GetMessageByID`, decrypts) then `history-service/internal/cassrepo/write.go:101,171-175` (`readEncryptedFields` re-SELECTs `messages_by_id` and decrypts again) because `decryptIfNeeded` discards the ciphertext (`decrypt.go:39-40`). Mutation path, so low volume.
- [low] Edit/delete mirror writes are serial round-trips — `history-service/internal/cassrepo/write.go:278-305`, `:366-389` — 2–4 sequential `Exec`s per mutation whereas `pin.go:69-81` and `reactions.go:36-50` group the same mirror set in one `UnloggedBatch`. Inconsistent, and each extra RTT sits on the client's request budget.
- [low] `ListThreadSubscriptions` hydration can issue 200 point reads in waves of 16 — `history-service/internal/service/threads.go:211` (parents ∪ last, `limit` ≤ 100) through `history-service/internal/cassrepo/messages_by_id.go:15,44-50` — ~13 serial waves of Cassandra RTT for a full page, each row then decrypted. The client-facing `msg.get.ids` caps at 100 (`messages.go:447`); this internal path does not.
- [nitpick] Epoch-mismatch logs once per room per request — `history-service/internal/mongorepo/room.go:122-126` — during a preview-key rotation a 100-room `rooms.get` emits 100 Info lines per call on every pod until warm-backs rewrite the docs.

### Recommendations

- [medium] Cache `previewEmpty` (short TTL, or key it on `NewestObservedID`/`createdAt`) and warm back an explicit "no preview" marker — `rooms.go:129-135`, `readcache.go:301-316` — removes the per-request bucket walk for dormant rooms, the dominant residual Cassandra cost of `rooms.get`.
- [medium] Switch `GetThreadRooms`/`GetFollowingThreadRooms`/`GetUnreadThreadRooms` to `AggregatePagedHasMore` (`collection.go:142-166`) and drop `Total` from the response, or cache the count — `threadroom.go:59-81`, `threads.go:323-342` — turns each page from O(N) sort+count into an indexed top-k.
- [medium] Add the required `// $lookup justification:` on `unreadThreadsPipeline`, and consider a `thread_subscriptions`-driven variant (match `userAccount`+`roomId` first, then join `thread_rooms`) so the join runs over the user's subscriptions rather than every thread in the room — `pipelines.go:136-162`.
- [medium] In `userThreadSubscriptionsPipeline`, evaluate a denormalised `lastMsgAt` on `thread_subscriptions` maintained by the same worker that stamps `thread_rooms.lastMsgAt` (revisit the §5 write-amplification estimate against measured reply rates), so the cursor `$match` and `$sort` can be index-backed before the joins — `pipelines.go:56-133`.
- [low] Hoist `iter.Columns()`/`buildScanValues` out of the per-row loop in `scanMessagesUpTo` and reuse one `vals` slice per iterator — `cassrepo/utils.go:146-165`, `messages_by_room.go:56-75`.
- [low] Size pages from the encoded bytes once: have `fitPage` return the marshaled prefix (or let the router accept pre-encoded bytes) so the reply is not encoded twice — `pagefit.go:63-92`, `utils.go:210-232`.
- [low] Pass the already-loaded ciphertext into `UpdateMessageContent` (or keep `EncPayload`/`EncMeta` on the model behind `json:"-"`) to drop the second read+decrypt on edits — `write.go:96-117`, `decrypt.go:36-40`.
