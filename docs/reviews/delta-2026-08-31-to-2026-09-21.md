# Audit delta — 2026-08-31 → 2026-09-21

Comparison of the two full-fleet production-readiness passes, three weeks apart,
over the same 35 services. Scores are parsed from the per-service reports in this
directory; code claims are verified against the two audit base commits
(`600fbd5` for the August pass, `1dfa2f3` for the September one).

## Headline

**Fleet 3.18 → 3.09 (−0.09). The movement is mostly not the code.**

Thirty-seven code commits landed between the audits, including all four fix PRs
the August pass recommended. But score movement does not correlate with code
change:

| Code churn in the service's own directory | n | mean Δ | mean \|Δ\| | down / up / flat |
|---|--:|--:|--:|---|
| Untouched (0 lines) | 10 | −0.05 | **0.15** | 4 / 3 / 3 |
| Touched (<200 lines) | 16 | −0.09 | **0.15** | 7 / 4 / 5 |
| Reworked (≥200 lines) | 9 | −0.13 | **0.20** | 6 / 3 / 0 |

Services whose code did not change at all moved as much as services that were
substantially rewritten. Seven of the ten untouched services moved, including
two of the four −0.3 drops (`hr-sync-worker`, `teams-room-creation`).

Finding volume tells the same story: **1,441 → 1,731 total (+20%)**, but
`critical` 24 → 23 and `high` 239 → 247 — essentially flat. All the growth is in
`medium` and below. Reviewers read the same code more closely; they did not find
materially more serious things.

**Treat cycle-to-cycle deltas under ±0.3 as noise.** Use the absolute scores and
the finding text, not the arrows.

**Performance is the one dimension that moved for a verifiable reason.** The
`pkg/jsretry` ack-deadline heartbeat (`heartbeat.go` does not exist at
`600fbd5`, does at `1dfa2f3`) plus the user-service badge-count parallelisation,
the room-worker Mongo read shaping and the broadcast-worker shed-retry fix.

**Test coverage did not move at all.** Both passes scored it the same way; the
August report already recorded a 1.5 mean and "34 of 35 below the floor". The
root cause is unchanged: no pipeline runs integration tests, and no pipeline
reads the coverage profile it writes.

**Code quality and integration falling by ~0.3 each is re-scoring.** The clearest
case: `GRAPH_TLS_INSECURE_SKIP_VERIFY` defaults to `true` in `teams-chat-sync`,
`teams-user-sync` and `teams-chat-member-sync` at *both* base commits — identical
code. August mentioned it 4× per report; September 11–12× and weighted it into
the score. Same defect, heavier penalty.

## The one regression worth acting on

**Last cycle's `inbox-worker` fix moved the stall rather than removing it.**

PR #453 introduced `membershipLaneCap(cfg.Consumer.MaxAckPending)` to size the
membership lane channel, with the comment *"the dispatcher can never park on a
full lane and starve the concurrent one"*. In the same file,
`buildConsumerConfig` promotes the **server-side** budget to
`federationMaxAckPending = 10 × stream.DefaultMaxAckPending` whenever the setting
is at its default — the same branch the lane cap reads.

So at the shipped defaults the lane holds **1,024** while the consumer delivers up
to **10,000**. The invariant the fix asserts is false, and a membership backlog
past 1,024 events parks the dispatcher and starves every other event type behind
the single sequential Mongo writer — the original symptom, at a higher threshold.
`lanes_test.go:88-107` uses the same number on both sides, so it cannot catch it.

Fix: size the lane from `consInfo.Config.MaxAckPending`, which `main.go:875`
already fetches, and make the test derive its channel size from
`buildConsumerConfig`.

## Findings that persisted untouched

Verified still present in the code at `1dfa2f3`:

- **`admin-service` revocation still leaves the session cache warm.**
  `UpdateUserPasswordAndRevoke` still returns only `error` and
  `DeactivateAndRevoke` returns `(*model.User, error)` — neither hands back the
  session IDs needed to bust `sessioncache`. Four of six experts found this in
  August; it was re-found in September via `botplatform-service`.
- **`upload-service` MIME filtering is still bypassable.** `resolveMediaType`
  still short-circuits on the client-declared Content-Type before any byte
  sniff, so a POST declaring `image/png` over SVG bytes clears the
  `image/svg+xml` blacklist.
- **`notification-worker` → `user-presence-service` `PresenceSnapshot` has no
  responder.** Third audit cycle with this open.
- **`push-notification-service` still dispatches to `LogDispatcher{}`** — code
  untouched between audits, score unchanged at 2.7.

## Reading the individual movers

- **`bot-message-worker` 2.5 → 1.8** is the largest drop, but its
  `store_cassandra.go` thread handling is byte-identical across the two bases;
  the only commit touching the service was #407. The thread-partition bug was
  traced end to end this cycle rather than introduced — the score caught up with
  the code, the code did not get worse.
- **`upload-service` +0.2** understates the SSRF fix, because that fix landed in
  `pkg/drive`, outside the service directory.
- **`push-notification-service`, `user-presence-service`, `roomlist-worker`,
  `teams-room-verify`** are flat on untouched code — the expected result, and a
  useful control for the rest of the table.
